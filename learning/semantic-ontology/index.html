Learning path · 02

Semantic ontology

Learn to make meaning explicit by defining concepts, entities, relationships, states, and rules that people and software can interpret together.

Path status

Curriculum outline.

The repository's existing content model is a worked example, not proof of a complete course or formal ontology standard.

Outcome

Build models that reveal assumptions.

By the end of the path, a learner should be able to define a bounded domain, distinguish classes from instances, create controlled vocabulary, model relationships and states, test competency questions, and publish the model with its limits.

Define the domain

Name the purpose, audience, scope, source language, and questions the model must answer.

Meaning has a boundary

Structure the model

Represent concepts, identifiers, relationships, constraints, lifecycle states, and provenance.

Make assumptions visible

Test interpretation

Use examples, counterexamples, queries, and stakeholder review to find ambiguity and omission.

Models require challenge

Sequence

From language to a testable knowledge model.

Vocabulary

Collect terms, definitions, synonyms, exclusions, and source contexts.

Entities and relations

Model what exists in the domain and how the parts connect.

States and provenance

Represent change, confidence, authorship, evidence, and version history.

Queries and review

Test whether the model answers real questions without inventing certainty.

Practice artifact

Produce a small, documented ontology.

The capstone artifact includes a domain statement, glossary, concept map, machine-readable representation, competency questions, sample records, provenance notes, and a list of known gaps.

Source shelf and correction

Learn from open semantic-web standards.

Begin with the W3C specifications for RDF 1.1 Concepts, OWL 2 Overview, and the SKOS Primer. They address different modeling needs; none is a universal answer for every domain.

Find an ambiguous definition or broken example? Open a specific correction issue.
