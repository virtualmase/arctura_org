Learning path · 01

Engineering judgment

Learn to make and communicate defensible technical decisions when requirements conflict, evidence is incomplete, and every option carries consequences.

Path status

Curriculum outline.

Public lessons and assessment rubrics are still being developed. This page defines the intended capability and sequence.

Outcome

Decide without pretending uncertainty disappeared.

By the end of the path, a learner should be able to frame a bounded technical decision, compare options against explicit criteria, identify failure modes, justify a choice, and define when that choice must be revisited.

Frame the decision

Separate goals, requirements, constraints, preferences, assumptions, and stakeholders.

What must be decided?

Reason with evidence

Evaluate source quality, missing information, uncertainty, and the cost of being wrong.

What supports the choice?

Own the consequence

Record tradeoffs, failure paths, decision rights, monitoring signals, and reversal conditions.

How will we know?

Sequence

From problem framing to review.

System and stakeholders

Define purpose, context, affected parties, and decision authority.

Constraints and options

Generate alternatives and expose the tradeoffs each one creates.

Risk and evidence

Test assumptions with failure analysis, source review, and uncertainty ranges.

Decision and revision

Write the rationale, monitoring plan, and conditions that reopen the choice.

Practice artifact

Produce an engineering decision record.

The capstone artifact is a concise decision record containing the problem, constraints, options, criteria, evidence, risks, selected path, dissent or uncertainty, owner, and review trigger.
