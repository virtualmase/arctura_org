Collective

One mandate. Three accountable layers.

The Collective is not membership and it is not a group to join. It is the name for how a decision, an authorization, and a verified action connect into a single reviewable record across Council, ARMS, and Protocol.

Composition, not a system

A mandate is the unit that travels.

No single surface owns a consequential action end to end. The mandate is what carries context between them.

How a mandate moves

Decision, authorization, verification.

1 · decides

Council frames it

A decision question enters through structured intake: stakeholder, time horizon, constraints, evidence available, required human approver. Council produces a sourced brief, not a decree.

Read how Council works →
2 · authorizes

ARMS authorizes it

The brief's decision becomes a mandate: purpose, allowed actions, prohibited actions, resource limits, duration, review interval, escalation owner. High-impact actions pause for human approval before anything executes.

Read the ARMS control stack →
3 · verifies

Protocol verifies it

Where a mandate involves payment, Protocol checks a submitted proof against the published verification rules and emits a confirmation event that downstream systems can act on under their own policy.

Read the Protocol status board →

Record

The record closes the loop.

Each layer's own receipt — decision record, execution receipt, verification event — references the same mandate. Reviewing the mandate means reviewing the full chain, not one surface's account of it.

Boundary

This is a record format, not a running system yet.

The composed mandate record described here does not exist as shipped infrastructure. Council, ARMS, and Protocol are each independently conceptual or early-stage; nothing currently issues a mandate that automatically threads through all three. Treat this page as the intended shape of the record, not a claim that it is live.
